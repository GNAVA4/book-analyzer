4.1. Ряды и колонки

Спаны PyMuPDF на одной высоте (|Δy| ≤ 2 pt) собираются в ряд. Двухколоночная страница определяется по промежутку x между колонками:

ряд k «разделён» в точке x ⇔ ни один фрагмент ряда не накрывает x, есть фрагмент целиком слева и фрагмент целиком справа;
H(x) = { k : ряд k разделён в x };   серии R ⊂ H(x) — максимальные подпоследовательности с разрывом ≤ 3 ряда;
страница двухколоночная в x*, если ∃ R: |R| ≥ 8 и |R| ≥ 0,4 · (последний(R) − первый(R) + 1); x* = argmax |R|.

Порядок чтения: участок из разделённых рядов читается сначала левой колонкой, потом правой; ряд во всю ширину (название, широкий рисунок) разрывает участок. Серия (а не вся страница) нужна потому, что на первой странице над колонками стоят шапка и аннотация во всю ширину и «разделённый» колонтитул: по всей странице колонок было 30% рядов, строки двух колонок перемешивались (найдено разметкой пользователя, s024). данные

4.2. Колонтитулы и номера страниц

Шум: строка в верхних/нижних 9% страницы, повторённая на ≥2 страницах (цифры нормализуются); строка на одной высоте на ≥3 страницах; голый номер страницы. Строки тела не трогаются («О.О. ВАРЛАМОВ» как автор на 1-й странице остаётся).

4.3. Абзацы

Новый абзац: интервал > 1,6 × обычного (с поправкой на кегль: строки названия 16 pt стоят реже), отступ первой строки относительно соседних (висячий отступ списка абзацы не дробит), короткая строка с точкой, смена кегля/стиля/письменности, «таблица/текст», слово-якорь («Аннотация», «Ключевые слова», «Список литературы»), строка оглавления с отточием («ЗАКЛЮЧЕНИЕ ....... 82» — всегда конец абзаца, иначе следующая страница «ВВЕДЕНИЕ» прилипала к оглавлению, s021). Переносы склеиваются: в конце строки и внутри строки («конфигу- рация» → «конфигурация», s024).

4.4. Заголовки

Отдельная строка жирным, крупнее или капсом, правдоподобная (не подпись, не пункт списка, не формула, не жирное предложение), за которой ≥ 100 знаков текста; либо заголовок в начале абзаца (жирный/курсивный фрагмент с точкой, слово из словаря «Введение.», «Выводы.»). Уровень — по нумерации «1.2.3».

4.6. Починка текстового слоя и язык

  • cp1251, прочитанный как latin-1 («Îïðåäåëåíèå» → «Определение») — по участкам строки (в строке бывает нормальная кириллица и формулы вперемешку); разрядка «П р и м е р» → «Пример».
  • Язык: > 60% латиницы в тексте вне шапки — статья на английском, из анализа исключается.
  • Скан: < 200 знаков текстового слоя на страницу → needs_ocr (OCR для статей не сделан).

Эффект правок парсера на корпусах (оборванные переносы «слово- Чужое», признак перемешанных колонок): 5522 → 2914 после исправления колонок; 322 документа пересобраны (corpus_build --reparse). Формат «Доклады АМАН» (аннотация после литературы) вернул в анализ 14 из 15 ложно «английских» статей.

5. Разбор DOCX (app/services/article_docx.py)

В DOCX структура размечена стилями — вёрстка не нужна. Заголовки — стили «Heading N»/«Заголовок N» (уровень N); если стилей нет — короткий целиком жирный абзац без точки. До первого заголовка — титул (название — первый жирный/центрированный абзац, авторы — «И.О. Фамилия»). Зоны по заголовкам: «Содержание» (пропуск), «Реферат/Аннотация», «Список источников» (литература), «Приложение» (пропуск). Подписи «Рисунок N», заглушки «[ … ]», короткие центрированные строки — не текст; пункты списка присоединяются к абзацу-вводу; таблицы пропускаются. Выход — тот же формат, что у PDF.

7. Фрагменты и эмбеддинги (app/analysis/semantic.py)

Фрагмент — единица смыслового сравнения, 300–1500 знаков: короткие абзацы раздела склеиваются до ≥ 300, длинные режутся по предложениям до ≤ 1500 (короткий абзац даёт шумный вектор, длинный — размытый). Фрагмент помнит номера абзацев (paras): метрики считаются по фрагментам, показываются по абзацам.

доля_букв(x) = (кириллические и латинские буквы) / (непробельные символы);  фрагмент формульный ⇔ доля_букв < 0,70

Формульные фрагменты исключаются из всех метрик (0,70 — 5-й перцентиль по 430 фрагментам; ниже — формулы, таблицы, код).

e(x) = v(x) / ‖v(x)‖,   cos(x, y) = e(x) · e(y)

v(x) — вектор модели text-embedding-qwen3-embedding-0.6b (LM Studio, контекст 8192 user). Кэш на диске по sha1(модель + текст): повторные прогоны мгновенны.

8. Метрики — формулы и обозначения

Обозначения: работа D — множество её фрагментов без формульных; документ корпуса B — множество его фрагментов; N(D) — документы для сравнения (соседи); a — фрагмент D.

8.1. Покрытие и выбор соседей

cov(D → B) = (1/|D|) · Σa∈D maxb∈B cos(a, b)   — «насколько содержание D уже есть в B» (асимметрично)
centroid(D) = нормированное среднее e(a), a ∈ D

Соседи N(D): (1) режим «та же тема» — документы с той же областью наук, «самые близкие» — без учёта темы, «весь корпус»; (2) фильтр по году — по умолчанию выключен user, опция «вышедшими не позже работы»; (3) 40 лучших по cos(centroid(D), centroid(B)); (4) 10 лучших из них по cov(D → B).

8.2. Похожесть абзаца, опора, категории

sim(a) = maxb ∈ ⋃N(D) cos(a, b);   ближайшая цитата = argmax;   опора(a) ⇔ sim(a) ≥ θопора = 0,56
КатегорияУсловиеСмысл
почти то же самоеsim ≥ 0,85та же мысль, часто пересказ
близко по смыслу0,75 ≤ sim < 0,85о том же, похожими словами
та же тема0,56 ≤ sim < 0,75текст на эту тему есть, мысль другая
не с чем сравнитьsim < 0,56ближайшее не отличить от текста чужой области; не новизна

Абзац получает значения своего фрагмента (короткие абзацы оцениваются вместе с соседями — помечается). Сводка по разделу/работе — доля текста (по знакам) в каждой категории.

8.3. Новизна

nov(a) = 1 − sim(a)
новизна(D) = среднее nov(a) по абзацам с опорой;   новизнасодерж.(D) = среднее nov(a) по абзацам с опорой и без воды (после проверки воды)

Почему так: в исходном определении (nov = 1 − max cos ко всему корпусу) новизна статьи коррелировала со сходством с ближайшей статьёй ρ = −0,92 (36 статей) — «новыми» были просто одинокие в корпусе статьи; и не была связана с водой (ρ = 0,03 по 554 абзацам): водянистый абзац на редкую тему выглядел новым. Поэтому — опора и исключение воды данные.

8.4. Смысловые повторы внутри работы

пара (aᵢ, aⱼ) — повтор ⇔ |i − j| ≥ 2, ни один не аннотация и не формульный, cos(aᵢ, aⱼ) ≥ τ = 0,82
повторы(D) = доля текста в абзацах, входящих хотя бы в одну пару

τ = 0,82 — верх ~1% распределения несоседних пар (5251 пара: p95 = 0,70, p99 = 0,79); все пары ≥ 0,83 при чтении — пересказ.

8.5. Дословные совпадения

основа(слово) = первые 6 букв;  S(x) = множество последовательностей из 5 основ подряд
cont(x, y) = |S(x) ∩ S(y)| / |S(x)|;   совпадение ⇔ cont ≥ 0,3 (абзацы с |S| ≥ 4)

Внутри работы и с абзацами соседей. Совпадение с аннотацией не считается повтором. Пересказ шинглы не ловят — это задача §8.4.

8.6. Самоцитирование и тема

самоцит(D) = |пункты литературы с фамилией автора D| / |пункты литературы|
тема(D) = argmaxобласть ΣB ∈ 7 ближайших размеченных max(0, cos(centroid(D), centroid(B))) · [область(B)];  уверенность = доля голосов

9. «Вода»: уровень утверждений (claims.py, water.py)

Эмбеддинги «воду» не видят: на синтетике водянистый абзац имел близость к теме 0,667 при медиане 0,691. Нужен уровень смысла — утверждения. Модель qwen3.6-35b-a3b разбирает абзац на атомарные утверждения с типом:

ТипЧто это
результатчто получено авторами (доказано, измерено, предложено)
фактконкретное проверяемое знание: определение, метод, свойство, чужой результат
общееоценки и общие слова без конкретики («актуально», «позволяет повысить эффективность»)
связкаметатекст: анонс, план, «в работе рассмотрено»
плотность(абзац) = 1000 · |результат ∪ факт| / знаков;   доля_общих = |общее ∪ связка| / |утверждений|
абзац водянистый ⇔ утверждений > 0 и доля_общих ≥ 0,5 (порог оставлен по решению user после разметки)

Рассуждение модели отключено закрытым блоком в шаблоне запроса к /v1/completions (<|im_start|>assistant\n<think>\n\n</think>\n\n): переключатели LM Studio не действуют, а думающая модель тратит весь лимит на рассуждение. Температура 0, три повтора — одинаковые ответы.

Не проза не проверяется (по разметке пользователя: все его «не могу сказать» — такие куски): подписи («б Рис. 7»), шаги алгоритма («Шаг 5.»), расшифровки формул («где Q — …», «x – …»), таблицы (цифр > 30% непробельных символов или разных слов < 55%), абзацы короче 200 знаков, формульные. На разметке: 7 из 8 «не могу сказать», 0 ложных на 32.

9.1. Фоновая задача и смена моделей

stateDiagram-v2 [*] --> idle idle --> queued: start(тексты) — только непроверенные queued --> loading: запрет сна Windows loading --> checking: lms unload --all → lms load qwen3.6 -c 4096 --parallel 1 checking --> checking: абзац → утверждения → para_claims (повтор ×3 при сбое) checking --> restoring: все / stop restoring --> done: lms unload --all → lms load эмбеддер -c 8192 done --> idle

Результаты хранятся по sha1 текста абзаца: повторная проверка мгновенна, прерванная продолжается с места. Пока идёт проверка, эмбеддер выгружен — загрузка нового файла отклоняется с объяснением (документы корпуса открываются). Скорость: 4,7–9 с на абзац; статья 2–5 мин, ВКР ~30 мин.

16. Ограничения и известные проблемы

  • Новизна относительна корпусу: на разношёрстном корпусе 60–96% текста «не с чем сравнить».
  • Эмбеддинги не отличают «ту же мысль» от «той же узкой темы»; категории 0,75/0,85 не проверены разметкой.
  • Остаточное перемешивание колонок (~2900 признаков на корпус) и текст изнутри схем/рисунков в абзацах.
  • Граница «результат/факт» у LLM размыта (на «воду» не влияет).
  • Сканы без текстового слоя не разбираются (OCR для статей не подключён); только русский язык.
  • Корпус «ИИ, информатика, математика» — только 2024–2026: режим «не позже работы» для ранних работ почти пуст.
  • После повторного разбора часть результатов «воды» привязана к старым текстам абзацев (проверено 1750 из 3278 абзацев КиберЛенинки).

17. Открытые вопросы (на обсуждение)

17.1. Эталон. Один эталон на тему не работает: для экономики и математики он разный, для каждого раздела свой, готовить вручную — нереально user. Варианты: (а) эталон из корпуса — типичное содержание темы = мысли/фрагменты, повторяющиеся во многих работах той же темы; покрытие = доля типичного, затронутая работой; «сверх» = содержательные абзацы далеко от типичного (нужно ≥10–20 работ на тему); (б) ожидаемое содержание раздела по названию от LLM (без ручных эталонов, нужна сильная модель); (в) методичка как чек-лист структуры, а не содержания.
17.2. Объём базы. Новизна и самоповтор требуют, чтобы нужные работы были в корпусе, а «бесконечную базу» не собрать user. Варианты: (а) только то, что есть в корпусе; (б) по запросу — при анализе подкачивать прошлые работы автора; (в) корпус по запросу — под каждую работу подкачивать 10–30 близких работ по ключевым словам и автору. Вопрос — источник: поиск КиберЛенинки без входа не работал (проверить), OpenAlex/Crossref — мало полных русских текстов.
17.3. Всё через нейросеть? Уровень утверждений точнее (вода, «та же мысль») но медленный: часы на корпус. Где граница между быстрыми эмбеддингами и LLM? Варианты: LLM только для проверяемой работы; LLM для корпуса один раз и кэш; новизна по утверждениям («какие мысли новые») — на обсуждение, решений нет user.
17.4. Новизна не по теме. Считать ли новизной текст не по теме работы (отступление про экономику в техническом отчёте)? Вопрос к руководителю.
17.5. Калибровка «та же мысль». Разметка пар отложена (во фрагментах часто нет утверждений, много читать). Альтернатива: синтетические пары (пересказ своих абзацев моделью) или сравнение утверждений LLM на малой выборке.
17.6. Повтор одной мысли. Повторы ищутся сравнением абзацев целиком; не видны повтор внутри абзаца и одна конкретная мысль в разных абзацах. Решение — сравнение утверждений работы между собой эмбеддером (быстро).

19. Ловушки окружения (сквозные уроки)

  • Системный прокси Windows (socks4) ломает httpx/openai: NO_PROXY='*' для pytest и uvicorn, trust_env=False в своём коде.
  • Полный pytest во время LLM-задачи JIT-загружает qwen2.5 в LM Studio (тесты этапа 1) → нехватка видеопамяти, ошибка 500.
  • Компьютер засыпает — фоновая проверка стоит (ночью простой 8,5 ч); теперь задача запрещает сон на время работы.
  • Видеопамять ≤ 90% (иначе пропадает дисплей): перед большой моделью выгружать все модели; 3.8 по умолчанию берёт 95%.
  • Правки кода через командную строку портят обратные косые черты в регулярных выражениях — только через редактор файлов.
  • Метрика «количество» не равна качеству: судить по содержимому (просмотр диффов при каждой правке парсера).
