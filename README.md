# Book Analyzer Service 📚

Система автоматизированной декомпозиции и структурного анализа электронных книг (PDF, DOCX, TXT) с преобразованием в иерархический XML.

Вместо «одного полотна» текста сервис восстанавливает логическую структуру документа (главы, разделы, подразделы), сопоставляет каждый раздел оглавления с его телом в тексте и отдаёт чистый XML с навигацией. Под капотом — **многоуровневый отказоустойчивый каскад**, где эвристика, локальная LLM, OCR и векторные представления (embeddings) дополняют друг друга: выпадение любого компонента не ломает конвейер целиком.

> 📐 Полное описание архитектуры со схемами — в **[ARCHITECTURE_v2.html](ARCHITECTURE_v2.html)** (открыть в браузере) / [ARCHITECTURE_v2.md](ARCHITECTURE_v2.md).

## 🌟 Основные возможности

- **Гибридный парсинг PDF** — быстрые детерминированные алгоритмы (regex + эвристика) с нейросетевыми резервами для сложных случаев.
- **Каскад извлечения оглавления (6 уровней)** — эвристика → LLM → OCR+эвристика → OCR+LLM → deep-scan → LLM-expand, с **выбором лучшего кандидата по «заземлённости»** (доля заголовков, реально встречающихся в тексте). Невалидированный вывод LLM в XML не попадает никогда.
- **Каскад сопоставления разделов (9 стадий)** — regex (4 стратегии) → ранняя верификация → page-hint → нечёткий → семантический (embeddings) → точечный LLM → финальная верификация → защита от смещения контента → нарезка по странице (page_cut).
- **OCR для сканов и битых кодировок** — локальная vision-модель `glm-ocr` + восстановление страниц, потерянных из-за ошибок API (HTTP 400).
- **Выбор источника тела книги** — сравнение текстового слоя и OCR-текста по качеству и охвату (а не по флагу читаемости).
- **Очистка контента** — удаление колонтитулов, **постраничных водяных знаков**, мусорных номеров, склейка переносов; трёхслойная защита от иероглифов-галлюцинаций LLM.
- **Поддержка DOCX** — структура по стилям + **интерпретация формул OMML** в читаемый текст.

## 🛠 Технологический стек

- **Backend**: Python 3.11, FastAPI, Uvicorn, WebSocket
- **PDF Engine**: PyMuPDF (fitz) 1.26
- **DOCX Engine**: python-docx, lxml
- **Нечёткий поиск**: difflib / RapidFuzz
- **AI Engine**: LM Studio (OpenAI-совместимый локальный API на `127.0.0.1:1234`)
  - LLM: `qwen2.5-7b-instruct` (контекст 8192)
  - OCR: `glm-ocr` (vision)
  - Embeddings: `text-embedding-qwen3-embedding-0.6b`

## 🚀 Установка и запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/GNAVA4/book-analyzer.git
cd book-analyzer
```

### 2. Виртуальное окружение и зависимости
```bash
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
```

### 3. Настройка локальной AI (LM Studio)
Для нейросетевого режима нужен запущенный **LM Studio** с локальным сервером на порту `1234`.

1. Скачайте [LM Studio](https://lmstudio.ai/) и запустите Local Server.
2. Загрузите три модели (имена должны совпадать с `id` из `GET /v1/models`):
   - `qwen2.5-7b-instruct` — **обязательно с контекстом 8192**, иначе на больших фрагментах будет `Context size exceeded`:
     ```bash
     lms load qwen2.5-7b-instruct -c 8192
     ```
   - `glm-ocr` — для OCR сканов и битых кодировок;
   - `text-embedding-qwen3-embedding-0.6b` — для семантического поиска.
3. **Выбирайте non-reasoning модели.** Reasoning-модели (Qwen3-thinking, DeepSeek-R1) тратят `max_tokens` на «размышления» и возвращают пустой `content`.

> ⚠️ **GPU ≤ 90%.** Не держите все три модели в видеопамяти одновременно — при 100% у пользователя пропадает изображение. Каскад вызывает модели **поочерёдно** (LLM / OCR / embeddings не резидентны одновременно), это штатное поведение.

> Имена моделей и `base_url` задаются в `app/services/llm_engine.py`, `ocr_engine.py`, `embedding_engine.py`. Алгоритмический (fast) режим работает **без** AI.

### 4. Запуск сервиса
Запускайте через Python из venv (надёжнее, чем глобальный `uvicorn`):
```bash
# Windows (из корня проекта):
venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# Linux/macOS:
venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```
Откройте браузер: **http://127.0.0.1:8000**

> ⚠️ Не запускайте две копии сервера на одном порту (частая ошибка при перезапусках) и не смешивайте `&` в shell с фоновым режимом инструмента — это плодит два Python-процесса. Перед перезапуском убедитесь, что старый процесс остановлен.

## 🧩 Как это работает (конвейер neural-режима)

1. **Читаемость** — `check_document_readability`: если текстовый слой — «кракозябры» и доступен OCR, страницы распознаёт `glm-ocr`.
2. **Оглавление** — `build_toc`: 6-уровневый каскад. Если эвристика выглядит неполной (алгоритмический триггер по числу строк-кандидатов), собираются кандидаты из разных источников, и `_select_best` выбирает лучший **валидированный** (формальная корректность + отсутствие иероглифов + заземлённость ≥ 0.8).
3. **Источник тела** — `_pick_body_source`: сравнение текстового слоя и OCR-текста; для маппинга берётся более качественный/полный.
4. **Очистка** — `clean_footer_header` (длинные колонтитулы) + сбор постраничных водяных знаков (`footer_junk_lines`).
5. **Маппинг** — `map_sequence`: 9 стадий поиска позиций разделов с двойной верификацией и `page_cut` как последним резервом.
6. **Нарезка и финальная очистка** — контент режется по позициям, из него вырезаются водяные знаки (`strip_junk_lines`), затем `fast_clean_chunk` (conf ≥ 0.85) или реконструкция через LLM (conf < 0.85); в конце — `scrub_foreign_script` на всех путях.
7. **Сборка XML** — `build_tree_structure` + `dict_to_xml`; у каждого `<section>` есть `title`, `page`, `confidence`, `chars`.

Ключевые понятия:
- **Заземлённость (grounding)** — доля заголовков оглавления, реально встречающихся в тексте; защита от галлюцинаций LLM (порог 0.8).
- **Нарезка по странице (page_cut)** — последний резерв: позиция раздела оценивается линейно как `(page−1)/total_pages × len(text)` (confidence 0.30), когда заголовок не находится строкой.

## 📂 Структура кода

**Транспорт и форматы**
- `app/api.py` — маршруты FastAPI: `POST /upload`, WebSocket `/ws/analyze`.
- `app/main.py` — точка входа Uvicorn (+ фикс cp1251/U+FFFD для Windows-консоли).
- `app/services/pdf_parser_neural.py` — **тонкий координатор** neural-конвейера (+ `_pick_body_source`).
- `app/services/pdf_parser_fast.py`, `docx_parser.py`, `txt_parser.py` — быстрые парсеры по форматам.

**Каскады**
- `app/services/toc_builder.py` — 6-уровневый каскад оглавления, smart fallback, `_select_best`, дедуп.
- `app/services/mapping_pipeline.py` — 9-стадийный каскад сопоставления, list-context, Class-2 фиксы, page_cut.

**Валидаторы и утилиты**
- `app/services/toc_validate.py` — оценка кандидатов ToC (формальная проверка, CJK, заземлённость).
- `app/services/toc_validator.py` — OCR-валидация оглавления.
- `app/services/toc_parser.py` — эвристический разбор оглавления (HeuristicParser).
- `app/services/pdf_utils.py` — поиск (`find_real_indices`), `fast_clean_chunk`, колонтитулы/водяные знаки, проверка читаемости.
- `app/services/content_quality.py` — детектор «мусорных» секций для аудита.
- `app/services/xml_builder.py` — генерация XML.

**Адаптеры моделей**
- `app/services/llm_engine.py` — клиент LLM (+ `scrub_foreign_script`, JSON-salvage, CJK-retry).
- `app/services/ocr_engine.py` — клиент glm-ocr (+ восстановление при ошибке 400, `_safe_print`).
- `app/services/embedding_engine.py` — клиент embeddings (семантический поиск).

**Инструменты разработки** — в `scripts/`: `run_corpus.py` (прямой прогон корпуса), `audit_content.py`, `analyze_xml.py`, `render_pages.py` и др.

## ✅ Результаты
Лучше всего система работает на документах с регулярной структурой (ВКР с чётким содержанием, академические учебники с нумерацией `N.N.N`, DOCX со стилями) — здесь не задействуются ни LLM, ни OCR. Хорошо, но с оговорками: книги без явного оглавления (через LLM-резерв), сканы и битые кодировки (через OCR). Ограниченно — тяжёлый OCR-дрейф в теле, заголовки крупным шрифтом, недетерминизм LLM. Подробный разбор — в [ARCHITECTURE_v2.html](ARCHITECTURE_v2.html), раздел 10 и 12.
