# Session 020 — 2026-10-18 — хранилище корпусов, анализ по абзацам, страница сервиса
← [session_019.md](./session_019.md)

## Session Intent
User: сделать хранилище корпуса и индексацию, загрузку PDF с быстрым проходом, отдельную
страницу; скачать много статей (экономика, математика, программирование…); корпуса
именованные, учитывать тему статьи и сравнивать с нужными статьями.

## Что сделано
- `scripts/fetch_cyberleninka.py` — скачивание по рубрикам (ищет последнюю страницу рубрики,
  берёт случайные из последней трети — там новые статьи; фильтр года ≥2015), рядом `.meta.json`
  (title, area=рубрика, year, url). Скачано 145 статей в `articles_cl/` (7 рубрик).
- `app/analysis/corpus.py` — CorpusStore (SQLite data/corpus.db: corpus/document/chunk+эмбеддинг),
  индекс в памяти, predict_area (kNN k=7 по размеченным документам всех корпусов), neighbours
  (scope topic/nearest/corpus, 10 ближайших по coverage среди 40 по центроиду). ADR 005.
- `app/analysis/article_report.py` — анализ статьи: тема, соседи, по абзацам (близость/новизна,
  опора, ближайший фрагмент корпуса с цитатой, смысловые повторы, дословные совпадения),
  сводки по разделам и статье. `semantic.make_chunks` теперь пишет `paras` (тексты фрагментов
  не изменились → кэш эмбеддингов валиден).
- `app/article_api.py` + `static/article.html` (/article.html): корпуса, список документов
  по темам, загрузка PDF, раскраска абзацев (близость / повторы / дословно), карточка абзаца,
  ссылка `?corpus=&doc=&para=`.
- `scripts/corpus_build.py` (папка → корпус), `scripts/corpus_calibrate.py` (тема LOO, порог опоры).
- Парсер: (1) аннотация/ключевые слова ПОСЛЕ литературы («Доклады АМАН») — раньше всё тело
  уходило в шапку и статья выпадала как «английская» (15 из 50); (2) двухколоночная вёрстка —
  строки левой и правой колонки на одной высоте склеивались; теперь `_find_gutter`/`_column_order`.

## Evidence
- Тесты: 382 passed (новые: test_corpus.py 6, TestColumns 2, TestTrailingHeader 1).
- Регрессия парсера на 45 старых статьях: аннотация-в-конце — изменились 2 (обе английские,
  исключены из анализа и до, и после); колонки — 15 изменились, просмотрены диффы:
  nn__ispolzovanie (двухколоночная) из каши стала связным текстом (+2200 знаков), остальные —
  перестановка обрывков формул (формулы из метрик исключены), graph__mnogokrit — склейка лучше.
- Корпуса: «КиберЛенинка» 119 статей (26 пропущено: 20 не русские/узбекские, 6 короче 3000 знаков),
  «Статьи этапа 2» 31 (сканы 3, англ. 6, короткие 5). Импорт 119 статей — 76 с.
- Калибровка: тема LOO 89/119 = 75%; близость своя/чужая область медиана 0.528/0.487,
  p90 «чужих» 0.561 → SUPPORT_SIM = 0.56 (первоначальные 0.60 давали 91% «без опоры» на 32 статьях).
- Сервис: /api/corpus-document — 0.3–0.7 с; загрузка PDF 80.pdf → тема ИТ 0.87, без опоры 91%
  (мивар-статей в КиберЛенинке нет). Мивар-статья в «Статьях этапа 2»: соседи — мивар-статьи,
  смысловые повторы 28%, дословно 18%. Скриншоты страницы (headless Chrome) просмотрены.

## Не сделано / открыто
- Уровень утверждений (LLM) в сервисе — фоновая очередь; новизна «только по содержательным» ждёт этого.
- MIN_BODY=3000 отсекает короткие настоящие статьи (expert__novyy 1887 знаков) — обсудить.
- Названия в новых журналах иногда = аффилиация («Сибирский федеральный университет…»).
- Сервер запускать с NO_PROXY='*' (импорт openai в api.py этапа 1).

Закоммичено. Сервер: `NO_PROXY='*' venv/Scripts/python.exe -m uvicorn app.main:app` →
http://127.0.0.1:8000/article.html (нужен LM Studio с моделью эмбеддингов для загрузки новых PDF).
