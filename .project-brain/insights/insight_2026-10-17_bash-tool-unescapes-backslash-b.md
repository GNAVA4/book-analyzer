# INSIGHT: Bash-инструмент разэкранирует `\\b` → backspace при правке кода через heredoc
_Filed: 2026-10-17 session 014_
_Category: tooling_

## The finding
Правка `article_parser.py` python-скриптом, переданным прямо в команде Bash (heredoc), с
регэкспами, содержащими `\\b` (в Python-строке = `\b` для re), записала в файл символ
`\x08` (backspace). Регэкспы `_ANCHOR_START` и `_NAME` молча перестали совпадать:
«Резюме», «Ключевые слова», «О.О. ВАРЛАМОВ» не находились. В выводе sed/grep символ невидим.

## How we found it
`ap._ANCHOR_START.match('резюме')` → None при визуально правильном паттерне;
`ascii(pattern[-40:])` показал `)\x08`.

## Action taken
Замена `chr(8)` → `chr(92)+'b'` через `python -c` с chr(), без литералов обратной косой.

## Applies when
Любая правка кода через Bash-команду с обратными косыми (`\\b`, `\\s`, `\\d` в строках).

## How to avoid
- Текст команды Bash проходит разэкранирование `\\` → `\` ДО bash (кавычки heredoc не спасают:
  патч, записанный через `cat > file <<'PYEOF'`, получил те же одиночные `\`). Дальше обычная
  (не raw) Python-строка превращает `\b` в backspace; `\s`, `\d`, `\[` выживают случайно.
- Правки кода — только Edit/Write. Патч-скрипт, если всё же нужен, писать через Write и с
  raw-строками (r"""…""") для заменяемого текста.
- После любой скриптовой правки проверять `open(f).read().count(chr(8)) == 0`.
