# INSIGHT: Qwen3.8-27B — нужен движок LM Studio ≥ 2.60; на нашей задаче в 3 раза медленнее 3.6 без явного выигрыша
_Filed: 2026-10-18 session 022 (обновлено после апдейта LM Studio)_
_Category: tooling / measurement_

## Загрузка
С движком llama.cpp 2.14.0: `missing tensor 'blk.64.ssm_conv1d.weight'` (65-й блок — голова MTP,
`nextn_predict_layers = 1`). Через CLI обновлений не было; user обновил LM Studio → движок
`llama.cpp-win-x86_64-nvidia-cuda12-avx2@2.60.0` — грузится за 15 с.
Закрытый `<think>` в /v1/completions работает и для 3.8 (ответ без рассуждения).

## Память (12 ГБ GPU, 31 ГБ ОЗУ, -c 4096)
- 3.8 по умолчанию (авто-offload, parallel 4): VRAM 11.7 ГБ (95%) — НАРУШАЕТ лимит 90%.
- 3.8 `--gpu 0.5 --parallel 1`: VRAM 10.6 ГБ (87%), свободной ОЗУ 2.9 ГБ. ← рабочая настройка.
- 3.8 + `--speculative-draft-mtp`: VRAM 11.0 ГБ (90%), скорость та же (11.8 vs 11.5 ток/с) — не нужно.
- 3.6 `--parallel 1` (авто): VRAM 8.0 ГБ (65%), свободной ОЗУ 1.6 ГБ.
- После обновления LM Studio эмбеддер по умолчанию грузится с ctx 8192 → указывать `-c 4096` [user].
